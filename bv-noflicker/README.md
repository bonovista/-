# BV-NOFLICKER v2 — 메인 → 진열화면 전환 때 사진 끊김

메인 사진을 눌러 NEW 같은 진열화면으로 넘어갈 때 사진 자리가 끊겨 보이는 문제를 고친다.
스킨 공통 레이아웃 `<head>` 의 `BV-NOFLICKER v1` 블록(2026-09-01)을 v2 로 바꾸는 것 하나로 끝난다. PC·모바일 블록은 같은 원문이다.

| 파일 | 내용 |
|---|---|
| `noflicker_v2.html` | 새 블록. v1 에서 바뀐 곳은 `[v2]` 로 표시 |
| `noflicker_v1_live.html` | 2026-11-20 라이브 v1 원문. 되돌릴 때 쓴다 |
| `apply_noflicker.py` | 레이아웃 파일에 v1→v2 교체·되돌리기·상태 확인. 블록 밖은 한 글자도 안 바꾼다(CRLF 그대로) |
| `test_transition.js` | 회귀 테스트. 라이브 페이지를 받아 블록만 바꿔 끼우고 크로뮴에서 프레임 단위로 잰다 |
| `compare_new_entry.jpg` | 전(v1)/후(v2) 모바일 NEW 진입 화면 비교 |

## 증상 — 2026-11-05 태진 화면녹화 (iPhone Safari, 60fps 실측)

메인 → NEW 를 두 번 들어갔는데 두 번 다 프레임 타이밍이 같았다. 회선 문제가 아니라 그리는 순서의 문제라는 뜻이다.

| 시점(NEW 첫 프레임 기준) | 화면 |
|---|---|
| 0–83ms | 머리·칩만 있고 목록 자리는 비어 있다 |
| 90–120ms | 목록이 들어온다. 사진 자리에 깨진 그림 아이콘(파란 "?"), 빈칸, 높이가 어긋난 카드가 섞여 있다 |
| 120ms | 사진이 한꺼번에 '툭' 켜진다 |
| 0–550ms | 이 모든 일이 본문이 아래에서 올라오는 슬라이드(`bvSlideUp`) 도중에 벌어진다 |

## 원인 — 2026-11-20 라이브 기준

1. **받는 중인 사진이 그대로 보인다.** 페이드도 숨김도 없다. JPEG 이 위에서부터 조금씩 그려지고(회색 띠), 사진마다 따로 '툭' 켜진다.
   모바일 목록 img 는 11-03부터 `srcset`(tiny·medium)과 `onerror`(실패하면 medium 으로 대체) 구조다.
   tiny 가 없는 상품(관리자 업로드분)은 실패하고 대체되는 사이에 깨진 그림 아이콘이 한두 프레임 비친다. 영상 속 "?" 의 가장 유력한 정체다. 오늘 확인한 NEW 앞 40장은 tiny 가 모두 있었다.
2. **첫 화면 사진도 `loading="lazy"`** 다. 레이아웃이 끝난 뒤에야 받기 시작한다.
3. **슬라이드를 1.8초에 무조건 끊는다.** v1 의 `setTimeout(function(){h.classList.remove("bv-slide");},1800)` 이다.
   머리의 동기 스크립트(`bv_gender.js` 약 300KB, `?d=` 가 10분마다 바뀌어 자주 다시 받음)가 늦으면 첫 그리기가 늦어진다. 그러면 1.8초 시점에 아직 올라오던 본문이 한 프레임 만에 제자리로 점프한다. 재현에서는 42–60px 을 점프했다.
4. **(PC) 사진 상자 높이가 정해져 있지 않다.** 받기 전 0px 이던 상자가 받은 뒤 368px 이 되면서 아래 내용이 밀린다. 모바일은 스킨에 `aspect-ratio:auto 2/3` 가 이미 있다.

영상 속 카드 높이 어긋남은 모바일 `aspect-ratio` 로 이미 해결돼 오늘은 재현되지 않는다.

## 고친 것 (v2)

- **슬라이드는 끝까지 간다.** 클래스는 `animationend` 에서 뗀다. 1.8초까지 시작도 못 했으면 그때 뗀다(시작 전이라 점프가 없다). 4초는 최후 안전판이다.
- **목록 사진은 다 받은 뒤 0.5초에 걸쳐 떠오른다.**
  - 받기 전에는 투명하다. 받으면 `bv-in` 이 붙어 페이드인된다.
  - 캐시나 뒤로가기로 이미 받아 둔 사진은 `bv-now` 로 바로 보인다.
  - 실패하고 대체되는 동안에도 투명이라 깨진 아이콘이 화면에 나오지 않는다.
- **첫 화면 사진 6장은 lazy 를 풀어 바로 받는다.** 앞 4장은 `fetchpriority="high"` 다.
- **사진 상자를 2:3 으로 미리 잡는다.** 상품 사진은 960×1440 이고, PC 에도 적용된다.
- **나중에 붙는 목록도 같은 규칙을 따른다.** 필터 카드(`bv_gender.js card()`)와 더 불러오기 목록을 MutationObserver 로 잡는다. 틀에서 복제돼 따라온 `bv-in` 은 지운다.
- **대상은 목록의 대표 사진 하나뿐이다.** 셀렉터는 `ul.prdList .thumbnail a>img:first-of-type` 이다. PC 마우스 올림 둘째 사진(`thumber_2`)과 품절 아이콘은 건드리지 않는다.
- **안전장치를 둔다.** 이 부분이 돌지 못하면 `bv-imgfade` 가 붙지 않아 v1 처럼 보인다. 동작 줄이기(reduce motion) 설정에서는 페이드 없이 바로 보인다.

## 검증 — `node test_transition.js live|v2` (크로뮴, 2026-11-20)

| 검사 | live(v1) | v2 |
|---|---|---|
| A 첫 그리기가 늦을 때 슬라이드가 끝까지 감 | **실패**: 100ms 지점에서 취소, 53px 점프 | 통과: animationend 뒤에 뗌 |
| B 모바일 NEW, 받는 중인 사진이 보인 프레임 | **141** ('툭' 4장) | 0 |
| B 첫 화면 사진 6장 요청 시작 | 87, 174, 174, 174, 174, 175ms | 6장 모두 86ms |
| C tiny 404 → onerror 대체, 깨진 사진이 보인 프레임 | 0–2 (크로뮴에서 흔들림) | 0 |
| D 필터 카드 40장, 받는 중인 사진이 보인 프레임 | **33** | 0 |
| E PC NEW, 받는 중인 사진이 보인 프레임 | **537** ('툭' 6장) | 0 |
| E PC 받기 전후 사진 높이 | **0px → 368px** | 368px → 368px |
| E PC 둘째 사진(thumber_2) 평소/마우스 올림 | 0 / 1 | 0 / 1 |
| B·C·D·E·F 받은 사진이 숨은 채 남음 | 0 | 0 |
| 합계 | 실패 5 / 12 | **모두 통과 12** |

- A 는 회선 속도와 상관없이 재현한다. 슬라이드가 80ms 쯤 진행됐을 때 페이지 시계를 1.8초 지점으로 당긴다.
- iOS 의 "?" 아이콘 자체는 크로뮴에서 그대로 나오지 않는다. 그래서 '받는 중이거나 깨진 사진이 화면에 보인 프레임 수'로 대신 쟀다. 배포 뒤 iPhone Safari 실기기 확인이 필요하다.
- 테스트는 m·www.bonovista.com 과 bv-data.bonovista30.workers.dev(필터 색인)에 닿아야 돈다. 사진을 뺀 HTML·스크립트·CSS 는 메모리에 캐시해 첫 그리기 시점을 일정하게 맞췄다.

## 적용

1. 카페24 관리자 → 디자인 편집에서 **PC 스킨과 모바일 스킨을 각각** 연다.
   `BV-NOFLICKER v1` 주석이 있는 공통 레이아웃 파일을 연다. 상세·게시판·로그인 화면에도 같은 블록이 들어가는 head 다.
2. `<!-- BV-NOFLICKER v1` 부터 `<!-- /BV-NOFLICKER -->` 까지를 `noflicker_v2.html` 내용으로 바꾼다.
   파일로 받아 작업한다면 `python3 apply_noflicker.py <레이아웃.html>` 을 쓴다. 원본은 `.bak_noflicker_v1_날짜` 로 남는다.
   v1 이 오늘 원문과 다르면 차이를 보여 주고 멈춘다.
3. 저장한 뒤 사이트 캐시를 삭제한다.
4. `node test_transition.js live` 를 돌려 모두 통과하는지 본다. iPhone Safari 에서 메인 사진 → NEW 를 두 번 들어가 본다.

되돌리기: `python3 apply_noflicker.py <레이아웃.html> --rollback`, 또는 `noflicker_v1_live.html` 원문으로 바꾼다.

## 남는 것

- 느린 회선에서는 사진을 다 받을 때까지 그 자리가 여백으로 남는다. 위에서부터 조금씩 그려지는 대신이다.
  필요하면 상자에 아주 옅은 바탕색을 깔 수 있다.
- `bv_gender.js` 는 10분마다 새 주소로 300KB 를 다시 받는다. 첫 그리기가 늦어지는 근본 원인이다. 별건이다.
